Quantization, Step by Step

A model is billions of numbers. Quantization stores each one with fewer bits. These five stations follow one number into its bits, then a few numbers into integer codes and back, and show what gets lost on the way.

2Absmax: from floats to integer codes

Nine values, stored as signed integers. The largest absolute value, α = 10.8, is mapped to the largest code. Every value is multiplied by the same scale s and rounded. Fewer bits: fewer codes, and values start to share one.

3One outlier stretches the range

Twenty-four ordinary values between −2 and 2, and one value of 256. The picture zooms in on the ordinary values. The vertical ticks are the codes: with the outlier, absmax spreads the codes so far apart that only three of them fall here. Clipping caps the range, so the codes move closer together.

Bits:
Clip at:

Clipping trades one error for many: the outlier is stored as the clipping value, and every ordinary value gets closer to a code. Which trade is right depends on how much the outlier matters.

4Lopsided values: the zero point

These nine values are all 0 or more, like the outputs of a layer that cuts off negatives. Symmetric absmax keeps codes for negative values that never occur. Asymmetric quantization maps the smallest value to code 0 and the largest to the last code; the zero point z is the code that stands for 0.0.

Move all values by: · 4 bits

5One scale per block

Sixteen weights of very different sizes, stored with 4 bits. With one scale for all of them, the large weights set the range and the small ones round to 0. Give each block of weights its own scale, and the small ones keep their values. Each scale costs 16 more bits.

Weights per block:
the weight what is stored, after rounding a weight rounded to 0 Bar heights: square root of the size, so the small weights stay visible.

Files in the GGUF format (llama.cpp) use this idea. Type Q4_0, for example, stores blocks of 32 weights at 4 bits, plus one 16-bit scale per block: 4 + 16 ÷ 32 = 4.5 bits per weight.
